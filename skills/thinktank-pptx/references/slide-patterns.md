# Slide Patterns — 定番スライドパターン集

日系シンクタンクの調査報告資料に頻出する11パターン。各パターンは「いつ使うか」「必要な入力項目」「構成」「実装ヒント」で構成。コンテンツは上流から入力として受け取る前提で、**必要な入力項目** が揃っているかをスライド設計前に確認する。色・フォントの具体値は `design-system.md` に従う。

## 1. 表紙

**いつ**: 資料の1枚目。

**必要な入力項目**: 資料タイトル(必須)、副題(事業名・調査名)、提出先、作成組織名、日付。

**構成**: 中央やや上に資料タイトル(2行まで)、その下に副題。下部に提出先(「〇〇省 御中」等)、作成組織名、日付。装飾は最小限 — ネイビーの水平線1〜2本のみ。

**実装ヒント**: タイトル24–28pt太字ネイビー。ロゴ画像がなければテキストの組織名で代替。背景は白のまま。

## 2. 目的・背景

**いつ**: 仕様書サマリー、調査の背景説明。読み手が既知の内容を確認的に示す場面。

**必要な入力項目**: 背景テキスト、目的テキスト。任意で仕様書の抜粋文と出典、目的達成までの段階(フロー化する場合)。

**構成**: タイトル+ボディのみ(メッセージなし)。ボディは「背景」「目的」等の見出し付きボックスを縦に並べ、入力テキストをみっちり記載。仕様書の抜粋を入れる場合は枠囲み+出典を明記し、その下に時系列フロー(横並びの矢印ボックス)で書き下すと分かりやすい。

**実装ヒント**: ボックスは極薄青(#DEEBF7)塗り+見出し12pt太字ネイビー。テキスト量が多くても可。ただし段落間にスペースを取り、重要語は青太字。

## 3. 調査内容・タスク分解

**いつ**: 業務・調査を構成するタスクの全体像を示す。

**必要な入力項目**: タスクのリスト(各タスクの名称+説明文)。タスク数は3〜5が収まりがよい。

**構成**: チャプター+タイトル(+必要ならメッセージ)。ボディはタスクごとのブロック。各タスクに **ナンバーボール(①②③ または 円形図形+数字)** を付け、太字タイトル+下線、その下に説明テキスト。論点・ポイントは青文字。

**実装ヒント**: ナンバーボールはネイビー円+白数字(直径0.6cm程度)。タスク間の行間を広めに取りスタイリッシュに。このボール番号は後続のスケジュール・課題・施策スライドと対応付けに再利用する。

## 4. 矢羽スケジュール

**いつ**: 調査・プロジェクトのスケジュール提示。**コンサルの定番スライド**。

**必要な入力項目**: 全体期間と時間単位(週/月)、タスクのリスト(各タスクの作業内容と実施時期)、節目イベント(MTG・委員会・報告等)の名称と時期。

**構成**: タイトル+ボディ(メッセージなしが普通)。
- 横軸: 週(W1, W2, ...)または月。表ヘッダーとして上部に配置
- 縦軸: タスク(左端列にタスク名。タスク分解スライドの番号と揃える)
- 各タスク行に **矢羽(チェブロン/右向き矢印型図形)** を期間分の長さで配置し、矢羽の中に作業内容(「判断基準整理」「ヒアリング」等)を白文字で記載
- クライアントMTG・委員会等の節目は **青い縦太線** を全行貫通で引き、上部にラベル(「中間報告」等)

**実装ヒント**: 矢羽は pentagon/chevron 図形。塗りはネイビー(主タスク)とブルー(サブタスク)で階層化。背景に薄灰の縦罫線で週区切りを示すと整列しやすい。MTG縦線は #2E75B6 2.5pt。

## 5. 論点整理

**いつ**: 調査で明らかにすべき問い(論点)の一覧化。

**必要な入力項目**: 項目(タスク・テーマ)のリストと、項目ごとの論点(問いの文)。論点中の強調キーワードが指定されていればそれも。

**構成**: チャプター+タイトル+メッセージ。ボディは項目ごとに: ナンバーボール+太字見出し(下線)+論点の箇条書き。論点中のキーワードは青文字。

**実装ヒント**: 行間設定が命(1.2〜1.3)。詰め込みすぎず、1項目3〜4論点まで。

## 6. スコープ定義

**いつ**: 調査対象と対象外の境界を示す。

**必要な入力項目**: 分類階層(大分類→中分類→小分類)の構造と、各要素の対象/対象外の別。

**構成**: チャプター+タイトル+メッセージ。ボディは **階層分類図**: 3階層ツリーまたは入れ子ボックスで全体集合を示し、**対象部分をネイビー/青塗り、対象外を灰色** にする。対象と対象外の違いだけでなく、対象内部の区分も同時に見せるのがポイント。

**実装ヒント**: 左から右への階層展開(左に大分類)。凡例(「■対象 ■対象外」)を右下に小さく置く。

## 7. 分析結果サマリー

**いつ**: 分析パートの冒頭または章末で結果を一望させる。

**必要な入力項目**: 結論となるメッセージ、評価表のデータ(行=対象、列=評価項目、各セルの評価値◎○△等)。任意で補足説明テキスト。

**構成**: チャプター+タイトルを上部にギュッと圧縮 → メインメッセージ → ボディの大きな表。表は評価項目×対象の形式で、**評価を記号(◎○△)+セル背景の濃淡(青グラデーション)** で見せる。図形・色は背景サポート役に徹し控えめに。

**実装ヒント**: ボディ面積を最大化するためメッセージは1行。表ヘッダーはネイビー塗り白文字。補足説明が必要なら表の直上に2行まで。

## 8. 分析詳細

**いつ**: デスクトップリサーチ結果、ヒアリング結果など情報を漏れなく伝える詳細ページ。

**必要な入力項目**: 詳細データ(ヒアリングなら対象者属性と発言要旨のペア、リサーチなら出典と要旨)。重要ファインディングスの指定があればそれも(なければ整形時に入力の結論部分から判断)。

**構成**: チャプター+タイトル+メッセージ+テキスト中心の表。ヒアリング結果は「対象者属性 | 発言要旨」の表形式。**示唆につながる重要ファインディングスを青太字** にして流し読みでも要点が拾えるようにする。

**実装ヒント**: テキストで見せ切ってよい(詳細スライドは網羅性優先)。1ページに収まらなければ同レイアウトで複数枚に分割し、タイトルに(1/2)(2/2)を付ける。

## 9. 2軸マトリックス

**いつ**: 要素が複数の軸にまたがって分布する場合の整理(例: 横軸=ライフステージ/バリューチェーン、縦軸=ステークホルダー/付加価値)。技術動向、施策マップ、検討範囲の提示に有効。

**必要な入力項目**: 縦軸・横軸の定義(軸名と区分)、プロットする要素のリストと各要素の位置(どの区分に属するか)。応用形を使う場合は回次情報や現状→将来の遷移情報。

**構成**: チャプター+タイトル+メッセージ。ボディは縦横の軸ラベル+グリッド。セルまたはグリッド上に要素ボックスをプロット。応用形:
- **回次プロット**: 検討委員会の第1回〜第4回がどの領域を扱うかを枠囲みでプロット→全体像と進め方が一目で分かる
- **現状→将来矢印**: 各要素の現在位置と将来位置を矢印で結び技術動向を示す
- **強調**: ポイントとなるセル・要素のみ赤枠

**実装ヒント**: グリッド罫線は薄灰。要素ボックスは極薄青塗り+細枠。軸ラベルは太字ネイビー。

## 10. 課題整理

**いつ**: 分析から抽出した課題の一覧化。提案パートへの橋渡し。

**必要な入力項目**: 課題のリスト(各課題の名称+説明文)、結論メッセージ。

**構成**: チャプター+タイトル+圧縮メッセージ+ボディ大面積。課題ごとに **ナンバーボール** を付けて列挙(課題名太字+説明文)。**この番号が次の施策スライドと連結する** ことが最大のポイント。

**実装ヒント**: 課題数は3〜6に絞る(入力の課題が多い場合はグルーピングを提案する。勝手に削らない)。ボール番号は施策スライドで同じ色・形を使い回す。

## 11. 課題・施策対応表 / 考察

**いつ**: 報告の集大成。課題と解決アイデアの対応、または調査結果からの考察・提言。

**必要な入力項目**: 対応表型は課題と施策のペア(課題名・課題概要・施策案)。考察型は調査結果のまとめテキストと考察テキスト、任意で概念図の構造情報。

**構成(対応表型)**: メッセージなしで「課題 | 課題の概要 | 解決に向けたアイデア(案)」の3列表をメインに。前ページのナンバーボールを課題列に再掲。セル内文字揃えは前後ページと一貫させる。

**構成(考察型)**: 情報がリッチになるため2つの見せ方を使い分ける:
- **図→テキスト**: 現状課題を概念図で大きく分かりやすく示し、その後に施策をテキストで詳述(読み手の心理的ハードルを下げる)
- **テキスト→図**: 結果をストーリーとしてテキストで書き下し、下に補助図を置く(テキストから入っても読み進められる)

入力テキストが構造化しにくい(まだ練られていない)論点は、無理に図解せずテキストでストーリー的に見せるのも有効な手段。

**実装ヒント**: 青文字・太字を多用して長文でも読み切れる工夫を。「今後検討を深めるべき事項」は2テーマ程度に絞る。

| 何をやるのか | 3. タスク分解 / 5. 論点整理 |
| いつやるのか | 4. 矢羽スケジュール |
| どこまでやるのか | 6. スコープ定義 |
| 何が分かったか(一望) | 7. 分析結果サマリー |
| 何が分かったか(詳細) | 8. 分析詳細 |
| どう分布しているか | 9. 2軸マトリックス |
| 何が問題か | 10. 課題整理 |
| どうすべきか | 11. 課題・施策対応表 / 考察 |
