# Think-Tank Style PowerPoint (thinktank-pptx)

日系大手シンクタンク(NRI / MRI / 日本総研 / MURC / みずほR&T)が官公庁委託調査の報告書等で用いるスライドスタイルを再現するスキル。

## 役割と責務分担

このスキルの責務は **デザインと構成への整形** に限定される:

- **やること**: 入力コンテンツのスライド構成へのマッピング、スライドパターンの選択、デザイン仕様(配色・レイアウト・強調)の適用、pptxスキルを使った実装
- **やらないこと**: 調査・分析・提案内容そのものの起案や深堀り。コンテンツは上流(ユーザーまたは別スキル)から入力として渡される前提

実装(.pptxファイル生成)は既存の **pptx スキル** に委譲する。本スキルは「何をどこにどう見せるか」を決め、pptxスキルが「どう作るか」を提供する。

## 全体ワークフロー

```
1. 入力受領   : 上流から渡されたコンテンツを入力項目定義に照らして確認
2. マッピング : コンテンツをスライド構成(章立て+スライド一覧)に割り当て
3. スライド設計: 各スライドの型・タイトル・メッセージ・ボディを設計
4. pptx生成   : /mnt/skills/public/pptx/SKILL.md を読み、設計に従い実装
```

**重要**: ステップ4では必ず `/mnt/skills/public/pptx/SKILL.md` を読んでから実装すること。

## ステップ1: 入力受領

### 入力項目定義

資料全体の生成に必要な入力項目。上流からの入力をこの定義に照らして棚卸しする。

| 項目 | 必須 | 内容 |
|---|---|---|
| 資料タイトル・副題 | ◎ | 表紙に記載する事業名・調査名等 |
| 資料タイプ | ◎ | 調査報告書 / 提案書 / 経営報告 / 部品単体 |
| 提出先・作成者・日付 | ○ | 表紙下部の記載事項 |
| 背景・目的 | ◎ | 仕様書サマリーや課題認識のテキスト |
| 調査内容・タスク一覧 | ○ | タスク名と説明(タスク分解・論点整理スライドの素) |
| スケジュール情報 | ○ | 期間、タスクごとの作業時期、MTG・委員会等の節目 |
| スコープ定義 | ○ | 対象・対象外の分類情報 |
| 分析結果・データ | ○ | 評価表、グラフ用データ、ヒアリング結果等 |
| 課題一覧 | ○ | 課題名と説明 |
| 施策・提案内容 | ○ | 課題に対応する施策案 |
| 考察・今後の検討事項 | △ | まとめパートのテキスト |

◎=必須、○=資料タイプに応じて必要、△=任意。スライド単位の部品依頼の場合は該当パターンの入力項目(`references/slide-patterns.md` の各パターンに記載)のみ確認すればよい。

### 入力が不足している場合

- 不足項目を列挙してユーザー(または呼び出し元)に確認する。**勝手に内容を創作して埋めない**
- 軽微な不足(日付、提出先など)は「●●●」等のプレースホルダで生成し、生成後にその旨を明示する
- 表現の整形(長文の要約、メッセージラインへの言い換え、箇条書き化)は本スキルの責務として行ってよい。ただし入力にない事実・数値・主張を加えないこと

## ステップ2: マッピング

入力コンテンツを章立てに割り当てる。調査報告書の標準章立て(入力にある項目のみ採用):

1. 表紙
2. 目的・背景
3. 調査内容・業務内容
4. 調査スケジュール(矢羽ガントチャート)
5. 論点・スコープ
6. 分析結果サマリー
7. 分析詳細(章ごとに複数枚)
8. 課題整理
9. 提案内容・施策案
10. 考察・今後の検討事項

提案書の場合は「背景・課題認識 → 提案概要 → 提案詳細 → 体制 → スケジュール → 条件」を基本形とする。

マッピング結果は生成前に簡潔に提示する(1スライド1行: 「No. | 型 | タイトル | 割当コンテンツ」)。一気通貫の指示がある場合は提示と同時に生成へ進む。

## ステップ3: スライド設計

### 基本構造(3層レイアウト)

シンクタンク資料の根幹。全スライドはこの構造を基本とする:

```
┌─────────────────────────────────┐
│ チャプター番号・章名(小) ＋ スライドタイトル │ ← 最上部
├─────────────────────────────────┤
│ スライドメッセージ(このスライドの結論1〜2行)  │ ← タイトル直下
├─────────────────────────────────┤
│                                 │
│   ボディ(表・グラフ・図解・テキスト)        │ ← 残り全面
│                                 │
└─────────────────────────────────┘
```

メッセージの有無はスライドの役割で決める:

- **メッセージあり**: 分析結果、課題整理、提案など「主張」があるスライド。メッセージは入力コンテンツの結論部分を1〜2行のセンテンスに整形して用いる。ボディ重視のスライドではメッセージを上部に圧縮しボディ面積を最大化する
- **メッセージなし(タイトル+ボディのみ)**: スケジュール、仕様書抜粋、一覧表など事実情報の提示が目的のスライド

### 各スライドで決めること

1. **型**: `references/slide-patterns.md` の11パターンから選択(該当なしの場合は基本構造に沿って設計)
2. **チャプター表記**: 「1. 調査概要」のような章番号+章名
3. **スライドタイトル**: 内容を示す体言止め(例: 「省エネ法と改正物効法の対応関係整理」)
4. **スライドメッセージ**: 入力の結論をセンテンスで(例: 「対象3業種すべてで非化石転換の検討が初期段階に留まっている」)
5. **ボディ設計**: レイアウト・図解形式・強調箇所

### デザイン原則(要点)

詳細なトークン(色コード・フォント・サイズ)は `references/design-system.md` を必ず読むこと。原則は:

- **色は青系に絞る**。表はネイビー→薄青のグラデーションでかっちり見せる。多色使いは厳禁
- **強調は青太字**(重要ファインディングス)、**最重要箇所のみ赤枠**。赤は囲み枠専用で、赤文字・赤塗りは使わない
- **ナンバーボール**で項目を構造化し、課題→施策のように後続スライドと番号で対応付ける
- **読み手の心理的ハードルを下げる配置**: 図解を先に見せてからテキスト詳細、またはテキストの下に補助図。テキストだけのページを連続させない
- **一貫性優先**: 表の文字揃え・配色・余白は資料全体で統一する
- テキスト密度は高くてよい(シンクタンク流)が、ボックス・下線・行間で必ず構造化する

## ステップ4: pptx生成

1. `/mnt/skills/public/pptx/SKILL.md` を読む
2. `references/design-system.md` のデザイントークン(色・フォント・配置座標)を実装に反映する
3. 設計したスライド構成を忠実に実装する。矢羽・ナンバーボール・マトリックス等の作図方法は `references/slide-patterns.md` の実装ヒントを参照
4. 生成後、全スライドを画像レンダリングして検品し(pptxスキルの手順に従う)、テキストのはみ出し・重なりを修正してから成果物を提示する

## Reference files

- `references/design-system.md` — 配色パレット、フォント、レイアウトグリッド、表・グラフのスタイル規定。**pptx実装前に必読**
- `references/slide-patterns.md` — 定番スライドパターン11種の構成・必要入力項目・実装ヒント。**スライド設計時に必読**
