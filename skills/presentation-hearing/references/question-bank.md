# Question Bank — 用途別ヒアリング質問集

Stage 2(構成案の設計)と Stage 3(ページ深堀り)で使う質問の引き出し。
そのまま読み上げるのではなく、ユーザの文脈(業種・聴衆・既出の回答)に合わせて
具体化して使う。既に会話や素材で分かっていることは聞かない。

## 共通(全用途)

- 表紙: 提出先(御中表記が要るか)/ 作成者(会社・部署・個人名)/ 日付
- 分量: ページ数の目安、発表時間(1枚1〜2分が相場)
- トーン: 社外フォーマル / 社内フォーマル / カジュアル
- 数値・固有名詞: スライドに載せる数字は出所を確認する(html-presentation の
  `.source` に入る。「出所不明のまま載せる」選択もユーザ判断としては可)

## 提案・企画書

構成の定石: 背景・課題認識 → 提案内容 → 効果 → 体制・スケジュール → 費用・次のステップ

- 相手が今困っていること・放置するとどうなるか(背景/課題)
- 提案を一言でいうと何か。競合・代替案と何が違うか(提案内容)
- 導入・実施すると何がどれだけ良くなるか。数値で言えるか(効果)
- 誰がやるのか。相手側に何をしてもらう必要があるか(体制)
- いつからいつまで、どんな工程か。判断してほしい期限はあるか(スケジュール)
- 費用・条件。段階提示(松竹梅)にするか(費用)
- この資料を読んだ相手に、次に何をしてほしいか(クロージング)

## 調査・分析報告

構成の定石: 目的・背景 → 調査概要(手法・対象) → 結果サマリー → 結果詳細 → 課題整理 → 考察・提言

- 何を明らかにするための調査だったか。誰の依頼か(目的)
- 手法(アンケート/ヒアリング/文献)、対象、件数、期間(調査概要)
- 一番の発見は何か。事前の想定と違った点はあるか(サマリー)
- 数値で見せられる結果はどれか。n数と出所(結果詳細)
- 結果から言える問題点は何か。3〜6件に整理できるか(課題整理)
- 課題に対して何をすべきと言いたいか。どこまで踏み込むか=提言か示唆か(考察)

## 社内報告・共有

構成の定石: 今回の要点 → 経緯・やったこと → 結果・学び → 次のアクション

- 忙しい人が1枚目だけ読むとしたら何を伝えるか(要点)
- 期間内にやったこと。予定との差分(経緯)
- うまくいったこと・いかなかったこととその理由(結果・学び)
- 次に何をするか。誰かに判断・協力してほしいことはあるか(アクション)
- 勉強会・技術共有の場合: 聴衆の前提知識レベル / デモ・コード例を載せるか /
  持ち帰ってほしいこと1つ

## スライド型別の深堀り質問

構成案で型が決まったページは、その型が必要とする情報を確実に聞く。

| スライド型 | 必ず聞くこと |
|---|---|
| 表紙 | タイトル・副題 / 提出先 / 作成者 / 日付 |
| 目的・背景 | 背景(現状)と目的(到達点)を分けて言えるか |
| タスク分解 | タスクは何個か(3〜5個が収まりがよい)/ 各タスクの一言説明 |
| 矢羽スケジュール | 全体期間 / 工程ごとの開始・終了 / 節目(報告・MTG)の時期 |
| 論点整理 | 論点は問いの形で何か / 項目ごとに3〜4個まで |
| スコープ定義 | 対象と対象外の境界 / 分類軸 |
| 分析サマリー | 評価軸(列)と対象(行)/ 評価は何段階か(◎○△×) |
| 分析詳細 | 定量なら数値と n数・出所 / 定性なら発言・事実の要旨 |
| 2軸マトリックス | 縦軸・横軸は何か / どのセルが重点か |
| 課題整理 | 課題は3〜6件か(多ければグルーピングを提案)/ 優先順位 |
| 対応表・考察 | 課題との対応関係 / 施策は「案」か「決定」か |

## アンチパターン

- 一度に10問ぶつける(4問以内に区切り、回答を反映してから次へ)
- 「内容を教えてください」と丸投げする(型に沿った具体的な問いにする)
- ユーザの「未定」を勝手に埋める(省略 or ドラフト提示→承認)
- 素材ファイルにある内容を聞き直す(確認だけで済ませる)
- 全ページの深堀りが終わるまで何も見せない(2〜4ページごとに確認文を見せる)
