# HTML Presentation (html-presentation)

パワーポイントの発表スライドのイメージで表示できるHTMLプレゼンテーションを生成するスキル。**プレゼン機能を持つHTMLベース(assets/base.html) + エンジンCSS(assets/engine.css) + デザインファイル(designs/*.css) + ユーザから渡されたプレゼン内容** を合成し、**HTML本体・エンジンCSS・デザインCSSの3ファイル**として出力する。HTMLは2つのCSSを `<link>` で参照する(スタイルはCSSファイル側に分離、HTMLは構造とスライド内容のみ)。3ファイルは同じフォルダに置いて一緒に配布する。

役割は thinktank-pptx スキルと同様に **構成とデザインへの整形に限定** する。内容の起案・深堀りはしない。

## 構成ファイル

```
html-presentation/
├── SKILL.md
├── assets/base.html          # HTMLひな形(構造+エンジンscript)。2つのCSSをlink参照
├── assets/engine.css         # エンジンCSS(16:9固定・自動スケール・印刷)。改変せずコピー
├── designs/thinktank.css     # シンクタンク調査報告書スタイル(標準デザイン)
│   └── (デザインは複数配置可。ファイル追加で差し替えられる)
├── references/slide-patterns.md  # 定番11パターンのHTMLスケルトン集
└── references/input-format.md    # 任意で受理する構造化入力(YAML)の契約
```

## ワークフロー

### 1. デザイン選択
`designs/` を列挙し、ユーザ指定があればそのデザイン、なければ `thinktank.css` を使う。**選択したデザインファイルを必ず読み**、冒頭のデザイン契約と禁則に従う。トークン(色・サイズ)を勝手に発明・変更しない。

### 2. 入力確認
渡された入力が **`.presentation.yaml`(または同等の構造化内容)** の場合は、`references/input-format.md` に従い各フィールドを3層構造へマップする(`presentation-hearing` 経由の入力がこれにあたる)。構造化入力が無ければ以降のとおり自由形式の内容から設計する。**この分岐は追加的で、単独呼び出し時の挙動は変えない。**
渡されたプレゼン内容を確認する。**入力にない事実・数値・文言を創作しない**。「ご清聴ありがとうございました」「CONFIDENTIAL」等の定型スライド・文言も指示がない限り追加しない。プレースホルダ「●●●」で残すのは表紙の定型要素(提出先・作成者・日付)のみ。それ以外の欠落要素は省略する。プレースホルダを使った場合は生成後にその旨を明示する。要約・言い換え・箇条書き化は責務として行ってよいが、入力に説明のない項目(タスク名のみ等)を言い換えで水増ししない(その要素は見出しのみ・省略でよい)。

### 3. スライド設計
`references/slide-patterns.md` を読み、内容を3層構造(チャプター+タイトル/メッセージ/ボディ)のスライドに割り当てる。生成前にマッピング(1スライド1行: No. | 型 | タイトル)を簡潔に提示する。一気通貫の指示がある場合は提示と同時に生成へ進む。

### 4. 生成(3ファイルを同じフォルダに出力)
出力名の基準を `<name>`(例: `presentation`)と決め、次の3ファイルを作る:

1. **`engine.css`** — `assets/engine.css` を**そのままコピー**(改変禁止)。ファイル名は固定 `engine.css`。
2. **`<name>.css`** — 選択したデザインファイル `designs/<デザイン>.css` を**そのままコピー**(改変禁止)。ファイル名はHTMLと同名(`<name>.css`)。
3. **`<name>.html`** — `assets/base.html` を読み、以下を置換して組み立てる:

| プレースホルダ | 置換内容 |
|---|---|
| `<!-- ===TITLE=== -->` | 資料タイトル |
| `===DESIGN_CSS_HREF===` | デザインCSSの相対パス(= `<name>.css`) |
| `<!-- ===SLIDES=== -->` | `<section class="slide">` の列 |

- `engine.css` への `<link>` はひな形に固定済み。**link の順序(engine → design)は変えない**(デザインが土台を上書きするため)
- **エンジン部(`engine.css` と base.html の `<script>`)は改変しない**。挙動を変えたい要望はスライド側HTML/デザインCSSで解決する
- **CSSはコピーであり、HTMLに再展開・要約・整形しない**(デザイン差し替えの互換性と原本一致を保つため)
- 外部CDN・外部フォント・JSライブラリは使わない(オフライン動作)。CSSは同フォルダのローカル相対参照のみ。**3ファイルは必ずセットで移動・配布する**(HTML単体ではスタイルが当たらない)
- スライドは1280x720前提で設計。収まらない内容は分割する

### 5. 検品
ブラウザ/スクリーンショットで確認できる環境なら、実際に `<name>.html` を開いて2つのCSSが読み込まれた状態で全スライドを検品し、はみ出し・重なりを修正する。できない環境では最低限 (a)3ファイル(`<name>.html`/`<name>.css`/`engine.css`)が揃い同フォルダにある (b)HTMLの `<link>` href が `engine.css` と `<name>.css` を正しく指す (c)スライド数がマッピングと一致 (d)プレースホルダ残置なし (e)デザイン外の色コード不使用 を確認して提示する。

## デザインの追加・差し替え

新デザインは `designs/<名前>.css` を追加するだけでよい。ただし thinktank.css 冒頭に記載の**デザイン契約クラス**(.slide / .cover / .slide-header / .chapter / .slide-title / .message / .slide-body / .footer / .source / .slide-no / strong)を必ず実装すること。スライドHTMLが契約クラスだけで組まれていれば、CSSの差し替えのみでデザインが切り替わる。

## 操作方法(生成物のクイックリファレンス)

| 操作 | 動作 |
|---|---|
| ← → / Space / Enter / PageUp・Down | スライド移動 |
| Home / End | 先頭・末尾 |
| F | 全画面(発表モード) |
| クリック(左端20%/それ以外) | 前へ/次へ |
| 左右スワイプ | 前後移動 |
| URL `#n` | nページ目から再開 |
| Ctrl+P | 1スライド1ページのPDF出力 |

## よくある失敗

| 失敗 | 正しい対応 |
|---|---|
| 金・えんじ等の独自アクセント色を追加 | デザインファイルのトークンのみ使用。thinktankは青系濃淡+赤枠のみ |
| 表紙・章扉を濃色グラデーションで装飾 | 背景は白。装飾はネイビー罫線のみ(.cover / .section-break を使う) |
| 「ご清聴〜」「CONFIDENTIAL」等を独断で追加 | 入力にない要素を創作しない |
| 円・ドーナツグラフ(conic-gradient) | 横棒グラフ(.bar-row)+青系濃淡 |
| キーメッセージを枠囲みボックス化 | .message はタイトル罫線直下のテキスト行(3層構造) |
| プレゼン機能(スケール・キー操作)を自作 | base.html のエンジンをそのまま使う |
| 収まらない内容をフォント縮小で詰める | スライドを分割する |
